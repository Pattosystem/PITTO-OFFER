# LIAS 単月提案プラン管理システム

仕様書 v1.0（2026-09-03）の **Phase 1（MVP）** を実装したもの。
既存の Pattosystem と同じく **GitHub Pages（単一HTML）+ Supabase** 構成。

## ファイル

| ファイル | 内容 |
|---|---|
| `lias-monthly-offers.html` | アプリ本体。これ1枚で動く |
| `schema.sql` | Supabase のテーブル定義（新規構築用） |

## 使い方

### すぐ触る（デモモード）
`lias-monthly-offers.html` をブラウザで開くだけ。26顧客・14商品・14ヶ月分の
サンプル購買データが自動生成され、R01〜R10 の候補が出た状態から始まります。
**保存はされません**（リロードで初期化）。利用者を切り替えると権限の違いも確認できます。

### 本番として使う
1. Supabase でプロジェクトを作り、`schema.sql` を SQL Editor で実行
2. `lias-monthly-offers.html` の冒頭 `CONFIG` に URL と anon key を記入
3. GitHub Pages に置く
4. 顧客・商品マスタを登録 → 購入実績CSVを取込 → 候補が生成される

```js
const CONFIG = {
  supabaseUrl:    'https://xxxx.supabase.co',
  supabaseAnonKey:'eyJ...',
  aiEndpoint:     '',   // 任意
  company: { name:'リアス株式会社', ... }
};
```

**注意**：anon key のままだと誰でも読み書きできます。運用前に `schema.sql` 末尾の
RLS を有効化し、Supabase Auth と `users.id = auth.uid()` を紐づけてください。

## 実装した範囲（§18 MVP）

- ログイン／権限（管理者・営業・閲覧者）。営業は担当顧客のみ表示
- 顧客・商品マスタ
- Bカート受注CSVの取込（Shift_JIS自動判別、列の自動対応づけ、受注番号＋受注内連番で
  重複防止、明細区分・対応状況での絞り込み、未登録の顧客/商品を自動登録）
- 顧客×商品×月の集計
- 判定ルール R01〜R10 + 6要素スコアリング + S/A/B分類 + 重複統合 + 抑制（§16）
- AI候補一覧（8種のフィルタ、顧客あたり上位3件表示、一括プラン作成）
- 顧客詳細（12ヶ月推移、商品別履歴、AI検知履歴、提案履歴と結果）
- 定例／個別／AI発見の3種プランを同一画面で作成、数量帯ごとの特別価格
- プランの下書き → 確定 → 送付。確定後も「下書きに戻して編集」で修正可、削除も可
- 粗利率・最低提案価格を下回る場合は警告（確定時に確認ダイアログ）
- 提案書プレビュー → PDF出力（ブラウザ印刷）、メール本文のコピー
- 送付登録・結果登録（受注/一部受注/見送り/失注/返信なし + 失注理由の複数選択）
- KPIダッシュボード、判定ルール別・商品別の受注率、失注理由集計
- 判定閾値の管理画面（§23の全パラメータ）、提案対象外リスト
- 監査ログ

## 仕様書からの実装判断（要確認）

1. **AI文章生成**（§13）
   ブラウザに生のAPIキーを置けないため、既定では**ローカルのテンプレート生成**で
   検知理由・顧客状況・仮説・推奨提案を作っています。根拠数値は必ず文中に埋め込むので
   「説明不能なブラックボックス提案の禁止」は満たします。
   LLMを使う場合は Supabase Edge Function を立て、`CONFIG.aiEndpoint` にURLを設定してください
   （`aiRefine()` から根拠値つきでPOSTします）。

2. **PDF出力**（§8.6）
   ブラウザの印刷ダイアログ経由（A4・余白16mm指定済み）。日本語フォントの埋め込み問題を
   避けるためで、レイアウトはそのままPDFになります。サーバー生成が必要ならPhase 2で。

3. **当月は集計対象から除外**
   R04（売上低下）の「直近2ヶ月」は、月の途中だと必ず低く出て誤検知するため、
   **完了した月だけ**で比較しています。

4. **R10（クロスセル）は顧客あたり1件**
   全未購入商品を候補にすると件数が爆発したため（実測で候補の7割）、
   同カテゴリで最も有力な1商品に絞りました。

5. **承認フローは廃止**（仕様書 §3 §8.5 §16 から変更）
   プランのステータスは 下書き / 確定済み / 期限切れ の3つ。粗利基準割れは
   確定をブロックせず、警告と確認ダイアログのみにしています。
   承認者ロールと approvals テーブルは削除しました。

6. **プランの削除**
   プラン、数量帯、対象顧客、提案書、送付記録、結果をまとめて削除します。
   元にしたAI候補は「未確認」に戻るので、翌月また候補として拾えます。

7. **認証**
   デモモードは利用者の切り替えのみ。本番は Supabase Auth + RLS が前提です。

8. **Bカート受注CSVの扱い**
   - 商品は**商品名で識別**します。商品管理番号は56%が空欄で、かつ同じ番号に
     別商品（SB009＝リジュランアイ／JALUPRO Young Eye）が入っていたためです。
     管理番号は参考情報として商品マスタに保存します。
   - 顧客は会員IDで識別。ただし「非会員」など数値でないIDは10社が共有していたため、
     `非会員｜会社名` の形に分割します。
   - 送料・値引きの行は取り込みません（設定画面で変更可）。
   - 取込で自動登録される商品は**通常価格・原価が空欄**です。粗利率の警告と
     提案書の通常価格表示は、値を入れるまで働きません。

9. **既存プロトタイプとの統合**（§24）
   `lias-monthly-offers.kotasail.chatgpt.site` の画面・項目はまだ差分確認していません。
   URLか画面キャプチャをもらえれば、残っている項目をこちらへ寄せます。

## 動作確認済み

- 全10画面の描画、候補生成→プラン作成→確定→提案書→送付→結果登録の一連の流れ
- 確定 → 下書きに戻す → 再確定、プラン削除で関連レコードが消えAI候補が復帰すること
- 販売停止商品・提案停止顧客が候補に出ないこと
- 候補の再生成が重複を作らないこと
- CSV再取込で全行が重複判定されること
- 権限による表示制御（閲覧者は設定不可、営業は担当顧客のみ）
